# Lectiva — приложение для конспектов студентов

Теперь с настоящим бэкендом на Supabase: авторизация по ссылке на почту,
данные (тетради, конспекты, флеш-карты, друзья, группы) хранятся в облаке
и доступны с любого устройства под своим аккаунтом — не только в браузере
одного компьютера, как было на localStorage-версии.

## Как подключить свой Supabase — обязательно перед первым запуском

1. Зарегистрируйтесь на [supabase.com](https://supabase.com) (бесплатно), создайте новый проект
2. В проекте: **SQL Editor → New query** — вставьте содержимое `supabase/schema.sql`
   целиком и нажмите **Run**. Это создаст все таблицы, индекс поиска и политики
   доступа (RLS)
3. **Authentication → Providers → Email** — включите Email (обычно включён по
   умолчанию); в **Authentication → URL Configuration** добавьте
   `http://localhost:1420` в Site URL и Redirect URLs — иначе ссылка для входа
   на почте будет вести не туда
3.5. **Вход через Google (необязательно, но уже подключён в коде):**
   в Google Cloud Console создайте OAuth-клиент (APIs & Services → Credentials
   → Create Credentials → OAuth client ID, тип — Web application), в качестве
   Authorized redirect URI укажите адрес, который покажет Supabase на вкладке
   **Authentication → Providers → Google** (вида
   `https://ваш-проект.supabase.co/auth/v1/callback`). Полученные Client ID и
   Client Secret вставьте туда же, в Supabase, и включите тумблер Google

4. **Settings → API** — скопируйте `Project URL` и `anon public` ключ
5. Скопируйте `.env.example` в файл `.env` в корне проекта и вставьте туда эти
   два значения
6. `npm run dev` — при первом заходе увидите экран входа: введите почту,
   перейдите по ссылке из письма — попадёте в приложение уже под своим
   аккаунтом

Без этих шагов (или с плейсхолдерами в `.env`) приложение откроет экран входа,
но письмо не придёт — Supabase ещё не настоящий.

## Вход: email+пароль или Google

Раньше был вход по ссылке на почту, теперь — обычная регистрация: почта,
пароль, юзернейм, пол (необязательно) и аватарка. Можно и просто войти
через Google. **Важно:** зависит от настройки "Confirm email" в вашем
Supabase (Authentication → Providers → Email) — если она включена (обычно
так по умолчанию), после регистрации придёт письмо с подтверждением, и
войти паролем можно только после перехода по ссылке из него. Если хотите,
чтобы можно было пользоваться сразу без подтверждения почты — выключите
эту настройку в Supabase.

**Если у вас уже была база с прошлого раза** — выполните ещё и
`supabase/migration_003_gender.sql` в SQL Editor (добавляет поле пола).

## Юзернеймы, аватарки и настоящие друзья

При первом входе теперь нужно придумать юзернейм (и можно загрузить аватарку) —
это отдельный "публичный" профиль, видный другим пользователям, в отличие от
приватного (там лежит только почта). Друзья теперь ищутся по юзернейму среди
реальных зарегистрированных людей, а не вписываются вручную как текст:
отправляете заявку → человек принимает или отклоняет → после принятия вы оба
видите друг друга в списке друзей.

**Если у вас уже был запущен основной `schema.sql` раньше** — выполните ещё
и `supabase/migration_002_real_friends.sql` в SQL Editor (Run), это добавит
новые таблицы, не трогая тетради и заметки, которые уже есть. Если ставите
проект с нуля — обновлённый `schema.sql` уже включает всё нужное, отдельная
миграция не требуется.

**ID пользователя.** У каждого пользователя есть короткий ID из 8 цифр
(виден в боковой панели и на странице «Друзья»), по нему можно найти друга.
Если `schema.sql` запускался до этого изменения — выполните ещё
`supabase/migration_004_public_id.sql`.

**Правила доступа.** Если `schema.sql` запускался до этого изменения — выполните
ещё `supabase/migration_005_security.sql`: он запрещает «дружить» без согласия
и создавать заметки/карточки в чужих тетрадях и наборах.

**Поделиться тетрадью.** Тетрадь можно открыть другу на чтение — он увидит её
на главной в разделе «Со мной поделились». Если `schema.sql` запускался до
этого изменения — выполните ещё `supabase/migration_006_sharing.sql`.

**Группы и чат.** Группы с участниками, вступлением по коду и общим чатом
(текст, фото, файлы; новые сообщения приходят сразу). Если `schema.sql`
запускался до этого изменения — выполните ещё
`supabase/migration_007_groups_chat.sql`.

**Поделиться модулем флеш-карт.** Как с тетрадями — друг может изучать, но не
менять. Если `schema.sql` запускался раньше — выполните
`supabase/migration_008_flashcard_sharing.sql`.

**Ссылки для мессенджеров, приглашения в группу, PDF.** Тетрадь или модуль
можно открыть по ссылке (Telegram, WhatsApp, VK, почта) — даже без аккаунта;
в группу можно добавить друзей или позвать ссылкой; конспект скачивается в PDF.
Если `schema.sql` запускался раньше — выполните
`supabase/migration_009_links_and_invites.sql`. Чтобы ссылки открывались у
других людей, приложение нужно опубликовать в интернете и указать его адрес
в `.env`: `VITE_PUBLIC_APP_URL=https://…`.

**Поиск по тексту конспектов и версия для телефона.** Поиск находит тетради
по тексту конспектов (с русскими словоформами); на телефоне вместо боковой
панели — нижнее меню. Если `schema.sql` запускался раньше — выполните
`supabase/migration_010_unshare_on_unfriend.sql` и
`supabase/migration_011_fulltext_search.sql`.

**Страницы внутри тетради.** В тетради может быть сколько угодно страниц
(«Лекция 1», «Семинар»…); уже написанные конспекты становятся «Страницей 1».
Если `schema.sql` запускался раньше — выполните `supabase/migration_012_pages.sql`.

**Тетради группы, отзывы и аналитика.** Выполните
`supabase/migration_013_group_notebooks.sql` и
`supabase/migration_014_feedback_analytics.sql`, если `schema.sql` запускался
раньше. Чтобы видеть страницу «📊 Аналитика», сделайте себя администратором
(один раз, в SQL Editor, со своей почтой):
`insert into admins (user_id) select id from auth.users where email = 'ваша@почта';`

**Файлы в Backblaze B2 (10 ГБ бесплатно).** Новые фото и файлы можно хранить в
Backblaze B2 через Cloudflare Worker (папка `worker/`): Worker проверяет вход в
аккаунт и кладёт файл в папку пользователя. Пока Worker не настроен, всё
хранится в Supabase Storage, а уже загруженные туда файлы работают и после.
Настройка: bucket в B2 (Private) и ключ доступа только к нему → заполнить
`B2_BUCKET`, `B2_ENDPOINT`, `B2_REGION` в `worker/wrangler.toml` →
`npx wrangler login` → `npx wrangler secret put B2_KEY_ID --config worker/wrangler.toml`
и то же для `B2_APP_KEY` → `npm run worker:deploy` → адрес Worker в `.env`:
`VITE_FILES_WORKER_URL=https://tetrad-files.….workers.dev`.

**Хранилище файлов.** Картинки, обложки, аватарки и PDF хранятся в Supabase
Storage (бакет `uploads`), а в базе — только ссылки на них. Если `schema.sql`
запускался до этого изменения — выполните в SQL Editor ещё и
`supabase/storage.sql`. Картинки сжимаются перед загрузкой (WebP, до 1600px),
размер одного файла — до 20 МБ.

## Что изменилось технически

- `src/lib/auth.ts` — вход по ссылке на почту (magic link), без пароля
- `src/lib/store.ts` — все функции (`getNotebooks`, `addNotebook`,
  `saveNote`, ...) теперь асинхронные и обращаются к Supabase вместо
  localStorage; сигнатуры и названия почти не поменялись, чтобы страницы
  менялись минимально
- Каждая страница (`Notebooks`, `Flashcards`, `Friends`, `Groups`,
  `NotebookEditor`) теперь загружает данные через `useEffect` + показывает
  "Загрузка…", пока идёт запрос
- Поиск (`SearchBar.tsx`) стал настоящим запросом к базе (`searchNotebooks`
  в `store.ts`), а не фильтрацией уже загрученного списка на клиенте
- `supabase/schema.sql` — обновлённая схема: у каждой таблицы есть
  `owner_id`, и Row Level Security гарантирует, что каждый видит и
  редактирует только свои записи

## Важное упрощение (осознанно, для MVP)

Картинки, вставленные в конспект, и файлы/PDF по-прежнему хранятся как
base64 прямо в тексте заметки (`notes.content`) и в `notes.attachments`
(jsonb), а не в Supabase Storage. Это значит:

- Всё работает и синхронизируется между устройствами уже сейчас
- Но крупные PDF или видео могут раздувать размер записи в базе — для
  учебных конспектов с несколькими фото/PDF за раз это некритично, но
  для продакшена правильнее перейти на Supabase Storage (загружать файл
  туда и хранить в тексте только ссылку) — это следующий логичный шаг,
  когда MVP обкатается

## Запуск

```bash
npm install
npm run dev
```

Откроется на http://localhost:1420

## Как это устроено

- `src/pages/` — экраны: тетради, редактор конспекта, флеш-карты, друзья, группы
- `src/components/DrawingOverlay.tsx` — рисование прозрачным слоем поверх
  конспекта и экспорт снимка (текст + рисунок) в PNG
- `src/lib/store.ts` — весь доступ к данным (теперь Supabase)
- `src/lib/auth.ts` — вход/выход, отслеживание сессии
- `src/lib/upload.ts` — загрузка файлов в Supabase Storage со сжатием картинок
- `supabase/schema.sql` — схема таблиц + политики доступа (RLS)

## Дальше — десктоп и мобильная версия

- **Десктоп:** приложение уже настроено под [Tauri](https://tauri.app) —
  установите Rust и Tauri CLI, затем `npm run tauri dev` соберёт нативное
  окно для Windows/macOS/Linux
- **Мобильная версия:** когда десктоп-версия обкатана, логику и часть
  компонентов можно перенести в React Native — `src/lib/store.ts` и типы
  в `src/types/` переиспользуются почти без изменений, так как это уже
  настоящий бэкенд, а не localStorage

## Чего ещё не хватает (следующие итерации)

- Реальный совместный доступ к тетрадям по шарингу (сейчас это ссылка-
  приглашение в мессенджер с текстом, а не выдача прав на просмотр/правку
  конкретному человеку в базе)
- Удаление файлов из Storage, когда удаляют группу (файлы из её чата остаются)
- OAuth-вход через ВКонтакте/Mail.ru — их нет в стандартном списке провайдеров
  Supabase (только Google, Apple, GitHub и ещё ~15 похожих сервисов), но их
  можно подключить через относительно новую функцию Custom OAuth/OIDC
  Providers (до 3 своих провайдеров на проект) — потребуется получить
  client_id/secret у самих VK/Mail.ru и настроить OAuth-эндпоинты вручную,
  это отдельная задача сложнее, чем Google
